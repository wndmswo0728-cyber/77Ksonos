# v1(기존) vs v2(열활성 hopping) 비교 — SONOS, Python ΔVT

- `flash_transport.py`(v1)는 **수정하지 않았다**. 지금 ATLAS로 돌리는 `generated/` 덱은 v1에서 만든 것이다.
- `flash_transport_v2.py`는 v1을 복제한 파일이고, hopping 항만 바꿨다(파일 맨 위 docstring 참고). 결과는 `generated_v2`에 따로 저장한다.
- 재현 방법: `python audit/v1_vs_v2/compare_v1_v2.py` → `compare_v1_v2.csv`

## 무엇을 바꿨나

| | v1 | v2 |
|---|---|---|
| hop 속도 | `hop_hz·exp(−2·dx/0.22 nm)·(Miller–Abrahams 인자)` | 확산계수 D = a²·ν·exp(−Ea/kT), 드리프트 속도 v = 2aν·exp(−Ea/kT)·sinh(qEa/2kT) |
| 거리 | dx = 계산용 plane 간격 → 결과가 격자에 의존함 | a = 물리적 hop 거리(트랩 간격) |
| 온도 | 전계 방향 hop은 온도와 무관함 | exp(−Ea/kT): 저온에서 얼어붙음 |
| 이산화 | 인접한 두 plane 사이 속도 | Scharfetter–Gummel 플럭스(연속체 극한과 일치) |
| 고전계 | — | 전계가 장벽을 낮추되 0 이하로는 내려가지 않음(속도 ≤ ν) |

## 결과 (77 K, plane 수 n = 4 / 8 / 16)

| 경우 | P−E (V), n=4 | n=8 | n=16 | ΔVT,PGM (n=16) |
|---|---:|---:|---:|---:|
| v1 기본 (현재 덱) | **−0.049** | +0.017 | +0.023 | 0.029 |
| v1 hopping OFF | +0.012 | +0.061 | +0.067 | 0.427 |
| v2 a = 1.5 nm, Ea = 1.2 eV | +0.012 | +0.061 | +0.067 | 0.427 |
| v2 a = 3.5 nm, Ea = 1.2 eV | +0.012 | +0.061 | +0.067 | 0.427 |
| v2 a = 1.5 nm, Ea = 0.6 eV | +0.012 | +0.061 | +0.067 | 0.427 |
| v2 a = 4.64 nm (N_t^−1/3), Ea = 1.2 eV | +0.027 | +0.002 | −0.000 | 0.029 |
| v2 a = 1.5 nm, Ea = 0.3 eV | −0.098 | +0.016 | +0.022 | 0.029 |

## 해석

1. **현재 덱(v1, n=4)에서 나온 역전(−0.049 V)은 수치 계산이 만든 결과다.** 격자를 n = 8, 16으로 늘린 경우에는 어떤 조건에서도 역전이 나오지 않는다.
2. **v2에서 물리적으로 그럴듯한 범위(Ea ≥ 0.6 eV, a ≤ 3.5 nm)는 77 K에서 hopping이 얼어붙는다.** 결과가 "hopping OFF"와 정확히 같다. 이때 n = 8 → 16에서 P−E가 +0.061 → +0.067 V로 수렴한다. 77 K SONOS 예측은 ΔVT,PGM ≈ +0.43 V, ΔVT,ERS ≈ +0.36 V, 창 ≈ **+0.065 V**이고 역전은 없다.
3. **hopping이 빠른 경우는 여전히 수렴하지 않는다.** 이 경우(a = 4.64 nm에서 장벽이 사라짐, 또는 Ea = 0.3 eV)는 n이 늘수록 Program ΔVT가 0.47 → 0.10 → 0.03 V로 떨어진다. 원인은 hopping 식이 아니다. 빠른 hopping이 전자를 차단막 쪽 가장자리 plane으로 몰고, 그 plane에서 게이트로 새는 WKB 누설이 plane 간격(dx/2)에 의존하기 때문이다.
4. **n = 4는 hopping을 꺼도 수렴하지 않는다**(+0.012 vs +0.067 V). v2로 덱을 만들 때는 n = 8 이상, 가능하면 16을 쓴다.
5. **300 K에서는 모든 경우 Program ΔVT가 0.02–0.03 V에 그친다.** PF 방출(광학 유전율 4로 계산한 장벽 저하 약 0.85 eV, 시도 주파수 10¹³ Hz)이 주입된 전하를 거의 다 내보내기 때문이다. 300 K에서 SONOS가 정상적으로 Program되는 실제 소자나 팀의 기존 300 K 시뮬레이션과 맞지 않는다. 따라서 77 K와 300 K를 비교하려면 PF 매개변수를 먼저 보정해야 한다.
6. 메모리 창 자체도 작다(약 0.07 V). 이 모델에서 SONOS는 −12 V, 500 µs로 정공이 거의 주입되지 않아 지워지지 않고, Program도 0.43 V에 그친다.

모든 수치는 Python ΔVT다. ATLAS 읽기 결과로 확인한 값이 아니다.
